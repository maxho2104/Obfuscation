# Вкладка «Дашборд» — описание задачи

Статус: реализовано в ветке `all_new_merged` (2026-11-17). Документ описывает,
что показывать на вкладке, откуда брать данные и как она встроена в приложение.

Практическая реализация: `internal_correspondence/reports/dashboard_service.py`
и `internal_correspondence/gui/dashboard_widget.py`; четвёртая KPI-карточка
показывает последний импорт оценок в головном офисе и количество
неэкспортированных изменений в филиале.

## 1. Назначение

«Дашборд» — обзорный экран для быстрой оценки состояния работы за выбранный период.
Он не заменяет вкладку «Статистика» и отчёты, а отвечает на вопросы «сколько сделано»,
«что требует внимания» и «как меняется динамика» без построения таблиц вручную.

Основные сценарии:

- руководитель филиала открывает приложение и сразу видит объём документов, долю
  оценённых материалов, состояние распределения задач и неэкспортированные изменения;
- сотрудник головного офиса видит сводку по всем филиалам, может выбрать филиал
  и сравнить его с остальными;
- после импорта оценок или изменений документов дашборд обновляется и показывает
  новые показатели.

## 2. Место в интерфейсе

Новая вкладка `Дашборд` в `QTabWidget` главного окна.

Предлагаемый порядок вкладок:

1. `Дашборд`
2. `Научные материалы`
3. `Телеграммы`
4. `Задачи`
5. `Статистика`

Дашборд делается первой вкладкой и открывается по умолчанию: это обзор, из которого
пользователь переходит в детальные разделы. Если менять порядок рискованно, допустимо
поставить его после «Статистики», но тогда он менее заметен.

Вкладка доступна обеим ролям. Данные ограничиваются ролью:

- филиал — только свой филиал;
- головной офис — все филиалы, с фильтром «Все филиалы» / конкретный филиал.

## 3. Фильтры

Верхняя панель:

- **Период**: `Год` / `Полугодие` / `Квартал` / `Месяц` (как на вкладке «Статистика»);
- **Год**: список доступных лет;
- **Полугодие / квартал / месяц**: зависит от выбранного типа периода;
- **Финансовый год (окт–сен)**: чекбокс, по умолчанию выключен;
- **Филиал** (только головной офис): «Все филиалы» или конкретный филиал;
- **Обновить**: ручное обновление;
- справа — подпись «Обновлено: ЧЧ:ММ».

Период по умолчанию — текущий календарный год. Для показателей задач, где используется
финансовый год, период считается по пересечению с выбранным диапазоном; это указывается
в подсказке к карточке.

в `QScrollArea`.

## 5. Карточки KPI

Карточка: название, крупное значение, пояснение, при наличии — изменение к предыдущему
периоду (зелёное/красное, со стрелкой).

### 5.1. Документы за период

- значение: количество научных материалов + телеграмм, у которых дата документа
  (`outgoing_date` или `incoming_date`) попадает в период;
- пояснение: «материалов: N, телеграмм: M»;
- сравнение: процент к предыдущему периоду той же длины; если предыдущий период пуст —
  «—», а не деление на ноль.

### 5.2. Оценено документов

- значение: доля документов, у которых есть хотя бы одна оценка (`latest_evaluation`),
  от общего числа документов периода;
- пояснение: «средняя оценка: 2,1» — среднее весов оценок (`enum_weight`) по последним
  оценкам документов, формат с одной десятичной цифрой;
- дополнительно: «материалов оценено: X из Y».

### 5.3. Задачи

- значение: «назначено / не распределено»;
- назначено — задачи, назначенные выбранному филиалу (или входящие в видимую область
  головного офиса) и пересекающиеся с периодом;
- не распределено — задачи, назначенные филиалу, но не имеющие назначений ни одному
  его потомку (отделу, группе, сотруднику); для головного офиса — задачи, не назначенные
  ни одному региону;
- пояснение: «из них просрочено: N» — задачи с `end_date < сегодня` и без полного
  решения (если признак решения появится; пока только по сроку).

### 5.4. Изменения

Для филиала:

- значение: количество записей `changes` — неэкспортированные изменения;
- пояснение: «последнее изменение: ЧЧ:ММ ДД.ММ.ГГГГ»;
- карточка подсказывает, что перед отправкой в головной офис нужно сделать экспорт.

Для головного офиса вместо неё — карточка **«Импорт оценок»**:

- значение: статус последнего импорта (`committed` / `rolled_back`);
- пояснение: «совпало N из M, ДД.ММ.ГГГГ»;
- при отсутствии импортов — «Импортов не было».

Допустим вариант с пятью карточками: «Документы», «Оценено», «Задачи», «Изменения»,
«Импорт»; тогда на узких экранах они переносятся в две строки.

## 6. Диаграммы

Все диаграммы — PyQtChart, как на вкладке «Статистика»; цвета берутся из текущей темы.

### 6.1. Динамика документов по месяцам

- столбчатая диаграмма с накоплением: материалы и телеграммы по месяцам периода;
- для периода «Месяц» показывается один столбец, для «Квартал» — 3, для «Полугодие» — 6,
  для «Года» — 12;
- подписи месяцев сокращённые; при наведении — точные значения;
- клик по столбцу (опционально, этап 2) открывает вкладку «Статистика» с этим месяцем.

### 6.2. Структура по типам

- круговая диаграмма (donut): распределение документов по типам;
- переключатель «Материалы / Телеграммы» над диаграммой;
- для материалов — `material_type`, для телеграмм — `telegram_type`;
- в центре — общее количество, в легенде — метка и доля.

### 6.3. Оценки по кодам

- столбцы по кодам `Б`, `И`, `П`, `В` с количеством документов;
- подписи значений над столбцами;
- рядом с заголовком — средняя оценка и доля оценённых;
- если оценок нет — заглушка «Нет оценок за период».

### 6.4. Филиалы / отделы: топ-5

- для головного офиса — горизонтальные столбцы по филиалам: количество документов
  за период; возможность переключить показатель «документы / оценки»;
- для филиала — по отделам;
- сортировка по убыванию, показываются 5 строк; остальные — в подсказке «ещё N».

### 6.5. Задачи по уровням (дополнительно)

Если карточки задач недостаточно, вторая строка диаграмм может содержать
горизонтальную диаграмму «Регион → Филиал → Отдел → Группа → Сотрудник»:
сколько задач назначено на каждом уровне и сколько из них не распределено дальше.
Это полезно головному офису, но увеличивает экран; на первом этапе можно ограничиться
карточкой и нижней таблицей «Требуют внимания».

## 7. Нижние таблицы

### 7.1. Последние документы

Не более 6 строк, только просмотр:

- тип (материал/телеграмма);
- исходящий номер и дата;
- наименование;
- филиал;
- последняя оценка (код и дата);
- двойной клик открывает карточку документа (этап 2).

### 7.2. Требуют внимания

Список-сводка, а не таблица документов:

- «Документы без оценки» — количество; переход на вкладку документов с фильтром
  (этап 2);
- «Задачи не распределены» — количество; переход на вкладку «Задачи»;
- «Неэкспортированные изменения» — количество (только филиал);
- «Ошибки/несовпадения последнего импорта» — количество (только головной офис).

На первом этапе достаточно строк «показатель — значение»; кликабельность — опционально.

### 7.3. Последние импорты оценок (головной офис)

3 последних журнала:

- номер журнала;
- дата импорта;
- документ (номер и дата);
- статус;
- совпало / не совпало.

## 8. Поведение и обновление

- при открытии вкладки данные загружаются один раз;
- при смене периода, года, фильтра филиала или финансового года — перезагрузка;
- после импорта, экспорта, изменения документов или задач главное окно вызывает
  `dashboard.refresh()`;
- во время загрузки показывается «Обновление…», контролы блокируются;
- ошибки чтения показываются в строке состояния/диалоге, пустые данные — заглушками,
  а не пустыми осями;
- дашборд только читает данные и не создаёт `Change`.

## 9. Данные и архитектура

Новый слой чтения, без изменения существующих сервисов:

- `reports/dashboard_service.py`:
  - `DashboardFilter(period_type, year, half, quarter, month, financial, branch_id)`;
  - `DashboardData(kpi, monthly, types, evaluations, ranking, recent_documents, attention)`;
  - `DashboardService(session, role, branch_id).load(filter)`.
- SQL-агрегаты, а не загрузка всех документов в Python:
  - `COUNT(*)` по материалам/телеграммам с фильтром периода и филиала;
  - `GROUP BY` по месяцам/типам/филиалам/отделам;
  - `COUNT(DISTINCT document_id)` для оценённых документов;
  - `COUNT(*)` по `changes` для филиала;
  - `COUNT(*)`/`GROUP BY` по `added_tasks` для задач;
  - последние `import_log` для головного офиса.
- Периоды переиспользуют `build_reporting_period`/`build_columns` из
  `reports/statistics_service.py`, чтобы не расходиться с вкладкой «Статистика».
- `gui/dashboard_widget.py`: контролы, карточки, диаграммы, таблицы; `apply_theme()`
  для перерисовки при смене темы.
- `gui/application.py`: вкладка, вызов `refresh()` после импорта/экспорта.

## 10. Производительность

- целевой объём: 10–20 тыс. документов, 1–5 тыс. задач;
- все показатели считаются агрегатными запросами; количество запросов — не более
  8–10 на одно обновление;
- индексы уже есть по датам/филиалам; при необходимости добавить составной индекс
  `(branch_id, outgoing_date)`;
- время обновления — до 2 секунд; при больших объёмах — кэш на время жизни фильтра.

## 13. Открытые вопросы

1. Делать дашборд первой вкладкой или после «Статистики»?
2. Достаточно ли 4 карточек, или нужны отдельные «Материалы» и «Телеграммы»?
3. Показывать ли для головного офиса сразу все филиалы или требовать выбор филиала?
4. Нужен ли финансовый год по умолчанию (сейчас предлагается календарный)?
5. Нужны ли клики по диаграммам с переходом в «Статистику»/«Задачи» на первом этапе?
6. Показывать ли «просроченные задачи» и по какому признаку считать просрочку?
7. Нужен ли экспорт дашборда в PDF/PNG?
8. Ограничивать ли дашборд только головным офисом для блока импорта?

## 14. Критерии приёмки

- вкладка «Дашборд» открывается без ошибок для роли филиала и головного офиса;
- фильтры периода и филиала меняют все показатели согласованно;
- карточки и диаграммы не падают на пустой базе;
- данные филиала не выходят за его филиал; головной офис видит все;
- обновление после импорта/экспорта отражает новые данные;
- на экране 1280×800 нет горизонтальной прокрутки, на 1920×1080 — читаемая сетка;
- тесты зелёные, GUI импортируется.
