# Система автоматизации учета и отправки/приема внутренней кореспонденции территориально-распределенной сети научных организаций

Приложение для автоматизации деятельности сотрудников делопроизводства территориально-распределенной сети (головная организация и филиалы) научных организаций по учету и отправке/приему внутренней корреспонденции.

## Описание

Система предназначена для автоматизации процесса учета и отправки/приема внутренней корреспонденции между филиалами научной организации и головным офисом. Приложение позволяет:

- Вести учет отправленных филиалом/принятых головным офисом научных материалов/телеграмм с указанием исходящих/входящих номеров и дат их присвоения
- Экспортировать пакеты документов, отправляемых из филиала в головной офис/импортировать пакеты, полученные от филиалов
- Импортировать оценки информационных материалов/телеграмм сторонними организациями / экспортировать эти оценки для передачи в филиалы из головного офиса
- Осуществлять планирование выполнения научных задач по филиалам в головном офисе, с дальнейшим распределением этих задач по отделам и исполнителям в филиалах
- Производить статистические подсчеты по количеству переданных/принятых научных материалов/телеграмм, количеству и значению оценок, выделению лучших/худших филиалов (в головном офисе), отделов и исполнителей (в филиале)
- Формировать информационные графики на основе результатов статистических расчетов
- Формировать отчетно-информационные документы на основе изменяемых шаблонов по результатам проведенных статистических расчетов
- Осуществлять быстрый поиск, фильтрацию и сортировку научных материалов/телеграмм по заданным пользователем критериям

## Стек технологий

- **Язык**: Python 3.10+.
- **GUI-фреймворк**: PyQt5 (Qt for Python). Выбран для совместимости с Windows и AstraLinux и возможностей Qt.
- **ORM**: SQLAlchemy 2.x. Обеспечивает единый способ работы с SQLite и PostgreSQL.
- **Миграции БД**: Alembic.
- **Базы данных**:
  - Филиал: SQLite, локальный файл на изолированной ПЭВМ.
  - Головной офис: PostgreSQL, локальный или центральный сервер; поддержка одновременной работы нескольких операторов.
- **Сборка**: `pyproject.toml` + PyInstaller.
- **Операционные системы**: Windows 7+, AstraLinux 1.6+.
- **Распространение**: один файл `.exe` (Windows) или исполняемый файл (Linux) с необходимыми зависимостями.

## Архитектурные решения

- **Change tracking**: каждая операция создания/изменения/удаления (CUD) над редактируемой сущностью порождает или обновляет запись `Change`. Экспорт сериализует только изменённые поля из `Change::changed_fields`.
- **Удаления**: фиксируются в поле `Change::operation_type` (2 — удаление) с очисткой множества полей, маркер в `changed_fields` не используется.
- **Дельта-обмен**: запись `Change` после экспорта не удаляется, а помечается датой экспорта (`exported_at`); следующие изменения накапливают поля только с последнего экспорта, что минимизирует объём передаваемых данных. Экспортированные записи удаляются по истечении срока хранения (настройка `changes_retention_days` в `settings.ini`, по умолчанию 30 дней; <= 0 — бессрочно).
- **Разрешение конфликтов**:
  - Научные задачи: побеждают данные головного офиса.
  - Научные материалы/телеграммы: филиал не редактирует входящие номера и оценки; остальные изменения филиала принимаются головным офисом с оповещением оператора о конфликте.
  - Справочники: головной офис абсолютно авторитетен.
  - ОШС: филиал авторитетен для своей структуры; UUID формируются с привязкой к филиалу для исключения коллизий.
- **Безопасность экспортных файлов**: ZIP-архивы не шифруются; безопасность передачи обеспечивается организационно-техническими мерами.
- **Настройки**: INI-файл в каталоге приложения; при отсутствии INI показывается мастер первого запуска.
- **Логирование**: `<app>/Logs/<YYYY-MM-DD>.log`, ежедневная ротация, хранение 30 дней.
- **Отслеживание изменений**: у каждой редактируемой сущности есть ссылка `change_id` на запись `Change` с последними неэкспортированными изменениями (см. раздел «Change tracking»).
- **Пакет предметной области**: перечисления, метки сущностей и полей, имена директорий и строки интерфейса вынесены из кода во внешний JSON-пакет (см. раздел «Пакет предметной области»).

## Пакет предметной области

Приложение отделяет бизнес-логику от предметной терминологии: все значения перечислений, метки сущностей и полей, имена служебных директорий и строки интерфейса определяются **пакетом предметной области** — JSON-файлом, подключаемым настройкой `domain_pack` в `settings.ini` (если настройка пуста, используется встроенный пакет `scientific-network`). Смена пакета меняет терминологию приложения под другую предметную область без изменения кода и бизнес-логики.

### Структура файла пакета

```json
{
  "id": "scientific-network",
  "version": "1.0.0",
  "enums": { ... },
  "entities": { ... },
  "directories": { ... },
  "strings": { ... }
}
```

- **`id`, `version`** (обязательные) — идентификатор и версия пакета. Записываются в `meta.json` каждого экспортного ZIP-архива; при импорте архива, созданного с другим пакетом или другой версией, оператор получает предупреждение.
- **`enums`** (обязательная) — перечисления. Ключ секции — имя перечисления (`material_type`, `evaluation_value`, `scientific_task_type`, `telegram_type`, `telegram_report_type`, `source_type`). Каждое значение:
  - `key` — семантический ключ (используется бизнес-логикой; должен совпадать с именем члена соответствующего IntEnum в `core/constants.py`, в нижнем регистре);
  - `code` — краткое текстовое представление (отображается в таблицах и комбобоксах как «метка (код)»);
  - `label` — отображаемое наименование;
  - `weight` — необязательный числовой вес (используется для оценок);
  - `deprecated` — необязательный признак устаревшего значения: скрыто из выбора, но его метка остаётся доступной для старых записей.
- **`entities`** — метки сущностей и полей. Ключ — имя ORM-сущности (например, `ScientificMaterial`). Поля: `label`, `label_plural`, `label_prepositional`, `label_prepositional_plural`, а также вложенный объект `fields` с метками полей (`label`, `short`, `required`). Переопределяет встроенные метаданные моделей; отсутствующие метки берутся из кода.
- **`directories`** — имена служебных директорий: `files`, `templates`, `export`, `material_files`, `telegram_files`.
- **`strings`** — строки интерфейса (заголовок приложения, меню, кнопки, сообщения). Ключи соответствуют полям `AppStrings` в `utils/string_resources.py`.

Полный пример всех секций — встроенный пакет `internal_correspondence/core/domain_pack.default.json`, который можно использовать как шаблон. Активный пакет выгружается в JSON-файл через меню «Данные» → «Пакет предметной области...» (после выгрузки файл можно сразу назначить активным — настройка применится после перезапуска).

### Правила совместимости

- **Ключи неизменяемы.** Семантический ключ — неизменяемый идентификатор значения: он определяет целочисленный код, хранимый в БД и экспортных файлах. Менять можно метки, коды-краткие-тексты и веса; выведенные из употребления значения помечаются `deprecated`, но не удаляются и не переиспользуются.
- **Целочисленные коды.** Колонки с кодами перечислений хранят целые числа (`SMALLINT`, значения IntEnum из `core/constants.py`: 0, 1, 2...); отображаемый краткий текст определяется активным пакетом по ключу. Связь «имя перечисления пакета ↔ IntEnum» — реестр `PACK_ENUMS` в `core/enum_registry.py`.
- **Валидация при загрузке.** Структура пакета проверяется при старте (обязательные поля, уникальность ключей и кодов, типы). При ошибке приложение предупреждает и работает на встроенном пакете.
- **Валидация БД при старте.** Числовые значения перечислений, сохранённые в БД, сверяются с активным пакетом (число → ключ → значение пакета); о неизвестных значениях выводится предупреждение (работа не блокируется — такие значения отображаются как есть).

### Пример: пакет для учебного заведения

```json
{
  "id": "university",
  "version": "1.0.0",
  "enums": {
    "material_type": {
      "label": "Тип работы",
      "values": [
        {"key": "message", "code": "С", "label": "Сообщение"},
        {"key": "document", "code": "ДОК", "label": "Курсовая работа"},
        {"key": "report", "code": "Д", "label": "Отчёт по практике"}
      ]
    }
  },
  "entities": {
    "ScientificMaterial": {
      "label": "Учебная работа",
      "label_plural": "Учебные работы",
      "fields": {
        "name": {"label": "Тема работы"}
      }
    }
  },
  "strings": {
    "app_title": "Учёт учебных работ"
  }
}
```

## Технические требования

- Приложение не изменяется в зависимости от места установки (филиал или головной офис), разница бизнес-логики регулируется настройками
- Данные хранятся в различных базах данных (например в филиале в SQLite, в головном офисе - Postgresql), бизнес логика не должна меняться в зависимости от СУБД
- Приложение должно быстро и стабильно обрабатывать большой объем записей в БД
- Приложение должно достаточно быстро и стабильно работать на слабых ПЭВМ с малым объемом оперативной памяти (от 4 Gb)
- Приложение должно стабильно функционировать на операционных системах Windows (версии 7 и выше) и AstraLinux (версии 1.6 и выше)

## Архитектура

Приложение представляет собой взаимоувязанную систему, включающую следующие компоненты:

**Подситема работы с записями о научных материалах/телеграммамах** - позволяет оператору добавлять, изменять, удалять записи об отправленных/принятых научных материалах/телеграммах, прикреплять к записям файлы, осуществляет их отображение в соответствии с заданными условиями фильтрации и сортировки
**Подсистема выполнения статистических подсчетов** - позволяет оператору осуществлять статистические подсчеты в соответсвии с введенными критериями, представлять их в табличной форме, отображать информационные графики на основе результатов этих подсчетов
**Подсистема импорта/экспорта** - позволяет формировать в филиале экспортный с данными по внесенным/измененным записям о научных материалах/телеграммах, а также с самими научными материалами (представленными в виде файлов на ЖМД) в сжатом виде, готовый к передаче по конфиденциальным каналам связи, а также раскладывать полученный файл на записи БД и прикрепленные файлы в головном офисе
**Подсистема формирования отчетов** - позволяет оператору формировать информационно-отчетные документы по результатам статистических подсчетов на основе изменяемых шаблонов
**Подсистема актуализации связанной информации** - позволяет оператору осуществлять ввод, изменение, удаление связанных данных, таких как: актуальные научные задачи, наименование и организационно-штатная структура филиала, распределение задач по сотрудникам и другие, как ручным вводом, так и посредством экспорта из файлов определенных форматов (json, xls и др.)

## Предполагаемая структура обрабатываемых данных

### Территориальная единица

Описание территориальной единицы (область, край, город и т.д.), в которой располагается филиал, содержит данные:

**Сокращенное наименование** - первичный ключ
**Наименование** - полное наименование территориальной единицы

### Филиал

Описание филиала научной организации, содержит данные:

**Индекс** - неизменямое буквенно-цифровое обозначение, первичный ключ
**Наименование** - полное наименование филиала
**Сокращенное наименование** - сокращенное наименование филиала
**Территориальная единица** - принадлежность к территориальной единице (отношение 1-n)
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Отдел

Описание отдела филиала, содержит данные:

**Идентификатор** - уникальный для всей системы uuid
**Наименование** - полное наименование отдела
**Сокращенное наименование** - сокращенное наименование отдела
**Филиал** - принадлежность к филиалу (отношение 1-n)
**Действительный** - является ли отдел действующим (True), или был сокращен (False)
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Рабочая группа

Описание рабочей группы, к работе в которой могут привлекаться сотрудники различных отделов филиала, в том числе и из различных филиалов, содержит данные:

**Идентификатор** - уникальный для всей системы uuid
**Наименование** - наименование рабочей группы
**Отдел** - принадлежность к отделу, от которого образована рабочая группа
**Комментарий** - дополнительная информация по рабочей группе
**Действительная** - является ли рабочая группа действующей (True), или была упразднена (False)
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Научное звание

Описание научных званий, содержит данные:

**Сокращенное наименование** - сокращенное наименование научного звания, буквенно-символьное, первичный ключ
**Наименование** - полное наименование научного звания
**Род. падеж** - полное наименование научного звания в родительном падеже русского языка
**Дат. падеж** - полное наименование научного звания в дательном падеже русского языка
**Порядок** - числовое значение для определения порядка при сортировке
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Сотрудник

Описание сотрудника, содержит данные:

**Научное звание** - указание на научное звание, которое может иметь сотрудник (отношение 1-n)
**Фамилия** - фамилия сотрудника
**Имя** - имя сотрудника
**Отчество** - отчество сотрудника (если есть)
**Отдел** - принадлежность к отделу (отношение 1-n)
**Должность** - должность сотрудника
**Рабочая группа** - принадлежность к рабочей группе (если есть, отношение 1-n)
**Начало работы в рабочей группе** - дата начала работы в рабочей группе (если работает в рабочей группе)
**Конец работы в рабочей группе** - дата окончания работы в рабочей группе (если работал в рабочей группе)
**Действительный** - является ли сотрудник действующим (True), или был уволен/переведен (False)
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Научная задача

Описание научной задачи, формулируемой руководством головного офиса. Головной офис распределяет научные задачи филиалам, филиалы в свою очередь - сотрудникам (филиалы также могут формулировать свои задачи и распределять их своим сотрудникам), содержит данные:

**Код** - символьно-цифровое обозначение, первичный ключ
**Наименование** - полное наименование научной задачи
**Тип** - содержит одно из возможных значений перечисления "Тип научной задачи"
**Начало действия** - дата начала срока, в течении которого должна решаться задача
**Конец действия** - дата окончания срока, в течении которого должна решаться задача (может не заполняться, в случае когда окончание срока действия доводится руководством позднее)
**Сотрудники** - ссылки на сотрудников, которым поручена работа по решению задачи (отношение n-n)
**Комментарий** - дополнительная текстовая информация по задаче
**Частичное решение** - числовое значение, при превышении которого задача будет отмечена как "Частично решена"
**Полное решение** - числовое значение, при превышении которого задача будет отмечена как "Решена"
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Страна

Краткое описание государства (страны), для случаев, когда в основу научного материала положены данные из зарубежных источников, содержит данные:

**Сокращенное наименование** - сокращенное буквенное наименование государства (страны), первичный ключ
**Наименование** - полное наименование государства (страны)

### Потребитель

Подразделение головного офиса (или сторонняя организация), рассматривающее научный материал и определяющее ему оценку, содержит данные:

**Индекс** - условное уникальное символьно цифровое обозначение, первичный ключ
**Сокращенное наименование** - сокращенное наименование потребителя
**Наименование** - полное наименование потребителя
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Источник

Краткое описание научного труда, легшего в основу аналитического научного материала или исследовательского оборудования, использованного в ходе экспериментов, содержит данные:

**Индекс** - условное уникальное символьно цифровое обозначение, первичный ключ
**Тип** - содержит одно из возможных значений перечисления "Тип источника"
**Комментарий** - дополнительная текстовая информация по источнику
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Руководитель

Краткое описание должностей в руководстве головного офиса сети научных организаций, которым представляют на доклад телеграммы, содержит данные:

**Сокращенное наименование** - сокращенное наименование должности руководителя, первичный ключ
**Действительный** - логический признак (True - если в адрес данному руководителю докладываю телеграммы, иначе - False)
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Файл

Описание файлов, прикрепляемых к отправляемым/принимаемым научным материалам/телеграммам (путь к прикрепляемому файлу в файловой системе расчитывается как <путь к файловому хранилищу>/"Путь"/"Имя"."Расширение", путь к файловому хранилищу задается настройками программы), содержит данные:

**Имя** - базовое имя файла в файловой системе (без расширения)
**Расширение** - расширение базового имени файла в файловой системе (например - doc/docx для документов Microsoft Word)
**Путь** - относительный (пути к файловому хранилищу) путь директории файловой системы, в которой хранится файл

### Научный материал

Описание передаваемого/принимаемого научного материала, содержит данные:

**Индекс** - уникальный для всей системы uuid, первичный ключ
**Тип** - содержит одно из возможных значений перечисления "Тип научного материала"
**Исходящий номер** - номер документа, согласно журналу учета, заполняемому сотрудниками филиала вручную (на каждый отчетный период, обычно год заводится новый журнал - т.е. номер уникален только в сочетании с датой присвоения)
**Дата исходящего номера** - дата присвоения исходящего номера согласно журналу
**Наименование** - наименование научного материала
**Входящий номер** - номер документа, согласно журналу учета, заполняемому сотрудниками головного офиса вручную (аналогично исходящему номеру)
**Дата входящего номера** - дата присвоения входящего номера согласно журналу
**Серийный номер** - серийный номер образца продукции или учетный номер передаваемого технического документа (в случаях, если передается образец продукции или технический документ, в остальных - не заполняется)
**Год выпуска** - год выпуска образца продукции или передаваемого технического документа (в случаях, если передается образец продукции или технический документ, в остальных - не заполняется)
**Номер разрешительного документа** - входящий номер документа, разрешающего передать образец продукции (в случае, если передается образец продукции или технический документ, в остальных - не заполняется)
**Дата разрешительного документа** - дата разрешительного документа (заполняется вместе с номером разрешительного документа)
**Стоимость** - стоимость образца продукции (в случае, если передается образец продукции, в остальных - не заполняется)
**Страны** - ссылки на государства (страны) происхождения данных, лежащих в основе научного материала (отношение n-n)
**Потребитель** - ссылка на потребителя научного материала (отношение 1-n)
**Филиал** - ссылка на филиал - отправитель научного материала (отношение 1-n)
**Отделы** - ссылки на отделы, сотрудники которых принимали участие в создании научного материала (отношение n-n)
**Сотрудники** - ссылки на сотрудников, принимавших участие в создании научного материала (отношение n-n)
**Рабочие группы** - ссылки на рабочие группы, члены которых принимали участие в создании научного материала (отношение n-n)
**Задачи** - ссылки на задачи, в рамках которых выпущен научный материал (отношение n-n)
**Источники** - ссылки на источники данных, положенных в основу научного материала (отношение n-n)
**Файлы** - ссылки на файлы, прикрепленные к научному материалу (отношение n-n)
**Комментарий** - дополнительная текстовая информация
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Телеграмма

**Индекс** - уникальный для всей системы uuid, первичный ключ
**Тип** - содержит одно из возможных значений перечисления "Тип телеграммы"
**Исходящий номер** - номер телеграммы, согласно журналу учета, заполняемому сотрудниками филиала вручную (на каждый отчетный период, обычно год заводится новый журнал - т.е. номер уникален только в сочетании с датой присвоения)
**Дата исходящего номера** - дата присвоения исходящего номера согласно журналу
**Наименование** - наименование (тема) телеграммы
**Входящий номер** - номер телеграммы, согласно журналу учета, заполняемому сотрудниками головного офиса вручную (аналогично исходящему номеру)
**Дата входящего номера** - дата присвоения входящего номера согласно журналу
**Страны** - ссылки на государства (страны) происхождения данных, лежащих в основе материалов телеграммы (отношение n-n)

**Сотрудники** - ссылки на сотрудников, принимавших участие в создании материалов телеграммы (отношение n-n)
**Рабочие группы** - ссылки на рабочие группы, члены которых принимали участие в создании материалов телеграммы (отношение n-n)

**Источники** - ссылки на источники данных, положенных в основу материалов телеграммы (отношение n-n)
**Тип доклада** - содержит одно из возможных значений перечисления "Тип доклада телеграммы"
**Адресаты доклада** - ссылки на должности руководителей, которым была доложена телеграмма (отношение n-n)
**Файлы** - ссылки на файлы, прикрепленные к научному материалу (отношение n-n)
**Комментарий** - дополнительная текстовая информация

### Адресация доклада телеграмм

Описание промежуточной структуры (таблицы базы данных), связывающей телеграммы с адресатами доклада (руководителями), содержит данные:

**Телеграмма** - ссылка на телеграмму (отношение 1-n)
**Руководитель** - ссылка на руководителя (отношение 1-n)
**Дата доклада** - дата, когда была доложена телеграмма руководителю; пустое значение означает, что телеграмма адресована руководителю, но ещё не доложена
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Оценка

Описание оценки материалов/телеграмм потребителем, содержит данные:

**Значение** - содержит одно из возможных значений перечисления "Значение оценки научного материала"
**Дата выставления** - дата, когда оценка была выставлена; определяет «последнюю» оценку документа
**Научные материалы** - ссылки на научные материалы, которым присвоена эта оценка (отношение n-n)
**Телеграммы** - ссылки на телеграммы, которым присвоена эта оценка (отношение n-n)
**Список оценок** - ссылка на список, включающий эту оценку (отношение 1-n, необязательное — оценка может быть выставлена вручную без списка)
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Список оценок

Описание документа, определяющего выставление оценок научным материалам и (иногда) телеграммам, содержит данные:

**Номер** - исходящий номер документа
**Дата** - дата присвоения исходящего номера
**Изменение** - ссылка на изменеие, произошедшее с сущностью (записью в таблице БД)

### Изменение

Описание изменений, произошедших с сущностью данных (записью в таблице БД)

**Дата и время изменения** - содержит дату и время записи изменеий сущности
**Сущность** - имя сущности (таблицы БД), в экземпляре (записи) которой произошли изменения
**Ключ сущности** - идентификатор (первичный ключ) сущности (записи в таблице БД), в которой произошли изменения
**Множество измененных переменных** - множество переменных (полей таблицы) сущности (записи), с которыми произошли изменения
**Тип операции** - вид операции над сущностью: создание (0), изменение (1), удаление (2)
**Дата экспорта** - дата и время записи данных сущности в экспортный файл; пустая — изменения ещё не экспортировались

### Связь задачи с сущностью

**Научная задача** - код научной задачи (первичный ключ сущности «Научная задача»)

## Использование

### Первый запуск

1. В появившимся диалоге "Параметры подключения к БД" указать параметры подключения ко вновь создаваемой базе данных (имя хоста (IP-адрес), имя базы данных, логин и пароль - для сетевых СУБД, имя файла на диске для SQLite). Наличие необходимых таблиц в базе данных проверит приложение, и в случае отсутсвия таковых - создаст их автоматически. Параметры подключения будут занесены в настройки и применяться при последующих запусках приложения.
2. Выбрать в меню "Данные"->"Расположение файлового хранилища". В появившемся диалоге выбрать директорию, которая будет являться корневой для файлового хранилища (Если пропустить этот пункт - по умолчанию корневой директорией файлового хранилища будет директория, в которой расположено приложение (для Windows) или директория пользователя (для AstraLinux)). Расположение корневой директории файлового хранилища будет занесено в настройки и применяться при последующих запусках приложения.
3. Выбрать в меню "Данные"->"Загрузка справочных данных".
4. В появившемся файловом диалоге выбрать файл из прилагаемого в установочного комплекта файла "Первичные данные.xlsx". (приложение автоматически заполнит данные для "Территориальных единиц", "Филиалов", "Стран", "Научных званий")
5. Еще раз выбрать в меню "Данные"->"Загрузка справочных данных".
6. В появившемся файловом диалоге выбрать файл из прилагаемого в установочного комплекта файла "Актуальные данные.xlsx". (приложение автоматически заполнит данные для "Научных задач", "Потребителей", "Руководителей")
7. Выбрать в меню "Данные"->"Роль".
8. В появившемся меню выбрать используемую роль (головной офис или филиал, для филиала в выпадающем списке выбрать наименование своего филиала). Указанная роль сохранится в настройках и будет применяться автоматически.
9. В меню "Данные"->"Изменение"->"Территориальные единицы" (/"Филиалы"/"Страны"/"Научные звания"/"Научные задачи"/"Потребители"/"Руководители"), в появившейся таблице проверить правильность заполнения данных. При необходимости произвести корректировку данных.

### Изменение организационно-штатной структуры филиала

Выбрать в меню "Данные"->"ОШС".

Диалог строится от элемента, от которого открыто приложение: филиал видит и редактирует только свою структуру (корень дерева - его филиал), головной офис видит все филиалы под корневым узлом "Головной офис" и может редактировать структуру (отделы, рабочие группы), но не записи о сотрудниках - их ведет сам филиал. В диалоге расположены два дерева одно под другим: "Штатная структура" (филиал - отделы - сотрудники, без рабочих групп) и "Рабочие группы" (филиал - отделы - рабочие группы - состав групп). По умолчанию развернут только корневой узел, остальные элементы раскрываются щелчком по узлу дерева. Неактивные (скрытые) элементы выделяются серым цветом; сотрудники сокращенного отдела отображаются как неактивные.

По двойному щелчку на элементе дерева справа выдвигается панель сведений: все данные элемента, а для сотрудника - таблица назначенных научных задач с возможностью добавлять ("+") и снимать ("-") назначения. В нижней части панели кнопки: "Скрыть" (закрывает панель), "Изменить" (открывает окно редактирования элемента), "Статистика" (закрывает диалог и открывает вкладку статистики с критерием, соответствующим элементу, и выделенной его строкой). Головному офису редактирование и назначение задач сотрудников недоступны.

### Статистические подсчеты

Открыть вкладку "Статистика" в главном окне.

Параметры подсчета: объект (научные материалы или телеграммы), критерий (сотрудники, отделы, рабочие группы, потребители, научные задачи, источники, полученные оценки; для головного офиса также филиалы), период (год/полугодие/квартал/месяц) и год (календарный или финансовый октябрь-сентябрь). Для критериев "Филиалы" (отделы, рабочие группы, сотрудники), "Отделы" (рабочие группы, сотрудники), "Рабочие группы" (сотрудники) и "Научные задачи" (сотрудники-исполнители) доступна подкатегория: строки элементов группируются по строкам критерия с выводом итогов группы.

Результат отображается таблицей с итогами и информационным графиком; область таблицы и графика разделяется перетаскиваемым разделителем. Тип графика переключается над графиком: столбцы, линии, круговая по итогам периода; при выбранной подкатегории на график выводятся элементы групп оттенками цвета своей группы. Кнопка "Экспорт в Excel" сохраняет результат (таблицу с итогами и изображение графика) в файл xlsx. Лучшее и худшее значения критерия выделяются цветом (зеленым и красным соответственно). Для критерия "Полученные оценки" дополнительно выводится средний балл по весам значений оценок. Кнопка "Рассчитать" обновляет результат.

#### Добавление записей об отделах/рабочих группах/сотрудниках

В диалоге редактирования организационно-штатной структуры:

1. В древовидном виджете диалога выбрать свой филиал и нажать кнопку "+" (или выбрать в контекстном меню (открывающемся по щелчку правой кнопки мыши) "Добавить отдел").
2. В появившемся диалоге заполнить необходимые поля и нажать "Ок".
3. Убедиться, что в древовидном виджете создан дочерний по отношению к выбранному филиалу элемент с наименованием отдела.
4. При необходимости внесения записей о других отделах повторить пункты 1 - 3.
5. В древовидном виджете выбрать нужный отдел и выбрать в контекстном меню "Добавить рабочую группу".
6. В появившемся диалоге заполнить необходимые поля и нажать "Ок".
7. Убедиться, что в древовидном виджете создан дочерний по отношению к выбранному отделу элемент с наименованием рабочей группы.
8. При необходимости внесения записей о других рабочих группах повторить пункты 5 - 7.
9. В древовидном виджете выбрать нужный отдел и нажать кнопку "+" (или выбрать в контекстном меню (открывающемся по щелчку правой кнопки мыши) "Добавить сотрудника")
10. В появившемся диалоге заполнить необходимые поля и нажать "Ок".
11. Убедиться, что в древовидном виджете создан дочерний по отношению к выбранному отделу элемент с сокращенным наименованием научного звания (при наличии), фамилией и инициалами сотрудника.
12. При необходимости внесения записей о других сотрудниках повторить пункты 9 - 11.

#### Скрытие записей об отделах/рабочих группах/сотрудниках

В диалоге редактирования организационно-штатной структуры:

1. В древовидном виджете диалога выбрать нужный отдел/рабочую группу/сотрудника (или выбрать несколько с используя множественный выбор при зажатых клавишах "Shift" или "Ctrl").
2. Нажать кнопку "-" (или выбрать в контекстном меню (открывающемся по щелчку правой кнопки мыши) "Скрыть").
3. Убедиться, что выбранные отделы/рабочие группы/сотрудники отображаются в древововидном виджете как неактивные (Неактивных сотрудников нельзя выбрать в диалоге создания/изменения научного материала/телеграммы, скрытие отдела влечет скрытие всех сотрудников данного отдела).

#### Удаление записей об отделах/рабочих группах/сотрудниках

В диалоге редактирования организационно-штатной структуры:

1. В древовидном виджете диалога выбрать нужный отдел/рабочую группу/сотрудника (или выбрать несколько с используя множественный выбор при зажатых клавишах "Shift" или "Ctrl").
2. Выбрать в контекстном меню (открывающемся по щелчку правой кнопки мыши) "Удалить".
3. В появившемся диалоге с вопросом "Вы действительно хотите удалить записи об отделе/рабочей группе/сотруднике/выбранне записи?" нажать кнопку "Да".
3. Убедиться, что выбранные отделы/рабочие группы/сотрудники больше не отображаются в древововидном виджете (Удаление записей об отделах, рабочих группах и сотрудниках влечет к изменению значений последующих статистических расчетов, применительно к научным материалам/телеграммам, при создании которых были задействованы соответстввующие отделы, рабочие группы и сотрудники, удаление записи об отделе ведет к удалению записей о всех сотрудниках отдела).

#### Изменение записей об отделах/рабочих группах/сотрудниках

В диалоге редактирования организационно-штатной структуры:

1. Дважды нажать левую кнопку мыши на отделе/рабочей группе/сотруднике, либо выбрать в контекстном меню (открывающемся по щелчку правой кнопки мыши) "Изменить"
2. Внести изменения в появившемся диалоге (переподчинение сотрудника в другой отдел можно выполнить выбором соответсвующего отдела в комбобоксе диалога, либо перетаскиванием элемента сотрудника на соответсвующий отдел в дереве "Штатная структура"; включение сотрудника в рабочую группу - перетаскиванием элемента сотрудника на группу в дереве "Рабочие группы").
3. Убедиться, что в древовидном виджете измененная запись об отделе/рабочей группе/сотруднике отображается корректно.

### Работа с записями о научных материалах/телеграммах

В основном окне программы переключиться на вкладку "Научные материалы"/"Телеграммы"

#### Добавление записи о научном материале/телеграмме

1. Нажать кнопку "Добавить"
2. В появившемся диалоге ввести необходимые значения и нажать кнопку "Ок"
3. Убедиться, что в таблице вкладки отобразилась и выделена сторка с вновь внесенной записью

#### Редактирование записи  о научном материале/телеграмме

1. В таблице вкладки дважды кликнуть левой кнопкой мыши по строке записи, которую требуется отредактировать
2. В появившемся диалоге внести необходимые изменения и нажать кнопку "Ок"
3. Убедиться, что в таблице вкладки отобразилась и выделена сторка содержащая внесенные изменения

### Удаление записей о научных материалах/телеграммах

1. В таблице вкладки выбрать строку (или несколько строк, используя зажатие клавиши "Shift" или "Ctrl") удаляемой записи и нажать кнопку "Удалить"
2. В появившемся диалоге предупреждения "Вы действительно хотите удалить запись (N записей)?" нажать кнопку "Да"
3. Убедиться, что в таблице вкладки больше не отображается строка (несколько строк) с удаленной записью (записями)

### Прикрепление и открепление к научным материалам/телеграммам файлов

1. Переключиться на вкладку "Научные материалы"/"Телеграммы" и указать строку с записью, для которой требуется изменить состав прикрепленных файлов
2. Выбрать в меню "Вид"->"Приекрепляемые файлы"
3. Убедиться, что в появившемся док-виджете "Прикрепленные файлы" (виджете прикрепленном слева или справа к основному окну, или отображаемому как самостоятельное окно) отображается заголовок "Файлы к научному материалу/телеграмме № <Номер научного материала/телеграммы>", а в списке ниже отражены прикрепленные файлы (список пуст, если прикрепленные файлы отсутсвуют)

#### Прикрепление файлов

1. В док-виджете "Прикрепленные файлы" нажать кнопку "+" и в появившемся файловом диалоге выбрать необходимые файлы или перетащить мышью необходимые файлы из окна стандартного проводника
2. Дождаться завершения процесса копирования (степень завершения процесса отображает всплывающий прогрессбар)
3. Убедиться, что в списке док-виджета "Прикрепленные файлы" отображены и выделены имена только что прикрепленных файлов
4. Убедиться, что в директории "<Директория файлового хранилища>/Файлы/Научные материалы (или Телеграммы)/<Дата исходящего номера научного материала (или Телеграммы, в формате "YYYY-MM-DD")>/<Исходящий номер научного материала (или Телеграммы)>" присутствуют скопированные файлы

Примечание: При указании на прикрепление файлов, находящихся в поддиректории файлового хранилища - копирование файлов не производится (добавляется только ссылка запись о файле в БД)

#### Открепление файлов

1. В док-виджете "Прикрепленные файлы" выбрать необходимые файлы и нажать кнопку "-"
2. Убедиться, что в списке док-виджета "Прикрепленные файлы" открепленные файлы больше не отображаются

Примечание: Физическое удаление файла происходит только в том случае, если данный файл прикреплен только к этому научному материалу/телеграмме. В случае удаления файла, запускается проверка на содержимое директории, содержащей файл и в случае отсутсвия в ней содержимого - производится ее удаление (рекурсивно, вплоть до директории файлового хранилища)

### Экспорт и импорт данных

#### Экспорт данных из филиала

1. Выбрать в меню "Данные"->"Экспорт"
2. В появившемся файловом диалоге указать путь и имя создаваемого экспортного файла (По умолчанию "<Текущая дата(в формате "ГГГГ-ММ-ДД").zip>")
3. Дождаться завершения процесса формирования и записи экспортного файла (степень завершения процесса отображает всплывающий прогрессбар)
4. Скопировать полученный экспортный файл на съемный носитель и отправить по каналам связи в головной офис

Примечание: По умолчанию в папке "<Директория файлового хранилища>/Экспорт сохраняется копия экспортного файла (на случай его повреждения или утраты)

#### Импорт данных в головном офисе

1. Скопировать полученный от филиала экспортный файл
2. Выбрать в меню "Данные"->"Импорт"
3. В появившемся файловом диалоге указать скопированный файл
4. Дождаться завершения процесса разбора экспортного файла (степень завершения процесса отображает всплывающий прогрессбар)
5. Убедиться в наличии изменений данных полученных из экспортного файла

## Особенности

### Общие

- В большинстве случаев данные из базы представляются пользователю в табличном виде
- Для представления большого объема данных должен быть реализован механизм пагинации (постраничного вывода)
- Для облегчения работы пользователей с данными должны быть реализованы механизмы фильтрации (отбора записей по заданным условиям) и сортировки
- Редактирование записей должно осуществляться посредством вызова соответсвующих диалогов
- Все изменения (в том числе создание и удаление), выполняемые пользователем с информационными сущностями (классами ORM, записями в БД), формируют ссылку на экземпляр (запись в БД) "Изменение" с соответсвующими записями. При изменении сущности, уже имеющей ссылку на изменения, имена множество измененных переменных сущности объединяется с множеством "Множество измененных переменных" "Изменения" ("Дата и время изменения" перезаписываются на текущее). В дальнейшем, при выполнении операции "Экспорт", формируется JSON - файл, содержащий данные записанные в сущностях, имеющих действительную ссылку на "Изменение" (данные выбираются из полей, перечисленных во "Множество измененных переменных"). По заверщении записи в JSON о сущности - ссылка на "Изменение" сбрасывается (в null), а экземпляр (запись) "Изменение" сохраняется с заполненной "Датой экспорта": последующие изменения накапливают "Множество измененных переменных" заново (дельта от последнего экспорта). Экспортированные записи "Изменение" удаляются по истечении заданного пользователем срока хранения.
- При отображении в таблице, измененные (но не экспортированные) строки выделяются (цветом) для обращения внимания оператора.
- Длительные ресурсоемкие процессы (такие как копирование файлов в файловое хранилище и из него, создание отправляемого и разбор принятого экспортного файла, сложные статистические расчеты) должны производиться в отдельных потоках с обязательным информированием оператора о ходе их выполнения (изменение значения прогрессбара)
- В диалогах редактирование записей поля обязательные к заполнению, а также уникальные поля должны быть выделены визуально. В случае незаполнения обязательного поля или несоблюдения требования уникальности - оператору должно выводиться сообщение.

### Работа с научными материалами и телеграммами

- Научные материала и телеграммы оцениваются по совокупности, т.е. может оцениваться как один научный материал (телеграмма), так и совокупность материалов и/или телеграмм. Таким образом оценка каждому научному материалу или телеграмме расчитывается следующим образом: "1/(<количество научных материалов, оцененных этой оценкой>+<количество телеграмм, оцененных этой оценкой>) <Сокращенное значение оценки>", например оценка научного материала, оцененного по совокупности с еще двумя научными материалами и двумя телеграммами (3 научных материала и 2 телеграммы) оценкой "Полезно" будет выглядеть - "0,2 П" ("1/(3+2) П").

## Стиль написания кода

- Создаваемый код должен быть хорошо комментируемым, иметь модульную структуру, обеспечивать его легкую поддержку и внесение в него изменений
- Описания информационных сущностей (классов ORM) должно быть отделено от реализации механизмов их использующих
- Работа механизмов отображения и корректировки данных не должна быть чувствительна к структуре и содержанию этих данных 
- Тексты заголовков диалогов, столбцов таблиц и других визуальных элементов должны быть тесно связаны с описанием информационных сущностей. Строковые значения (списки и словари их содержащие) присваиваемые этим текстам должны описываться в одному программном модуле (для облегчения перевода на другие языки)
